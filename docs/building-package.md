# Building package

How a client's building gets from the approved drawings into the 3D viewer. The viewer (`public/architecture.js`) is the same for every project; each project supplies a **building package**: one glTF model and a small JSON manifest.

```
public/buildings/<project>/
  building.glb     the model, exported in metres, Y up
  building.json    name, defaults and overrides (often a few lines)
```

A page shows it with `<canvas id="architecture" data-building="/buildings/<project>/building.json">`. Without `data-building` the viewer shows the demo tower (`public/building-tower.js`).

## 1. Model the exterior

Work from the approved plans and elevations in SketchUp, Revit, ArchiCAD or Blender. Model what a buyer sees: façades, slabs, balconies, glazing, roof amenities and the immediate site. Leave out structure and services that sit behind finishes.

- **Units:** metres, with the ground floor at about y = 0 and Y up, which is glTF's convention. Blender's glTF exporter converts from Z up automatically.
- **Budget:** aim for under 300,000 triangles and under 150 materials. Static geometry is merged per material on load, so object count matters less than material count.
- **Materials:** use plain PBR (base colour, roughness, metalness). Textures are kept but cost download time; the sky provides the reflections.

## 2. Name three kinds of nodes

| Node | Name | What the viewer does with it |
|---|---|---|
| Floor | `level_<n>`, e.g. `level_7` | Opens the building floor by floor (step 02). Put each floor's slab, façade and units under its level. Anything outside a level travels with the lowest one. |
| Home | `unit_<id>`, e.g. `unit_705` | The volume a buyer picks; it turns green, amber or grey with availability. It can be a single box inside the glazing or a group of meshes (merged into one). The id must match the sales inventory. |
| Point of interest | `hotspot_<key>`, e.g. `hotspot_pool` | An empty where a labelled hotspot appears. Clicking it flies the camera there. |

The same information can be given as custom properties (glTF *extras*) instead of names, which is useful when names are generated by the CAD export:

| Property | On | Meaning |
|---|---|---|
| `level` | floor node | floor number |
| `elevation` | floor node | slab height in metres (otherwise the lowest point of the level) |
| `unitId`, `floor`, `facing` | home | id; floor (otherwise its level); the direction it faces in radians, 0 = +Z (otherwise away from the building's centre) |
| `hotspot`, `view`, `normal` | point of interest | key; camera `{theta, phi, r, x, y, z}`; the side it is visible from |

## 3. Export

Export **glTF Binary (.glb)** with *+Y up*, *Apply modifiers* and custom properties included (Blender: *Include › Custom Properties*). Save it as `building.glb`.

## 4. Manifest

`building.json` needs only `version` and `name`; everything else is optional.

```json
{
  "version": 1,
  "name": "Residencia 01",
  "model": "building.glb",
  "floors": {"default": 7},
  "levels": {"1": {"elevation": 0}},
  "units": {"705": {"facing": 3.1416}},
  "hotspots": {"pool": {"view": {"theta": 0.95, "phi": 0.82, "r": 34, "x": 3, "y": 42, "z": -4}}},
  "frame": {"width": 30, "height": 48, "depth": 22, "y": 21},
  "night": {"materials": ["lobbyGlass"], "color": "#ffcf96", "intensity": 0.7},
  "merge": true
}
```

- `floors.default`: the floor shown first in step 02.
- `frame`: overrides the camera framing that is otherwise computed from the model's bounds.
- `night`: materials (by name) that glow after dark, such as lobby glazing; dark by day, then `color` (or their own emissive colour) at up to `intensity`.

## 5. Check before publishing

```
node site/tools/check-building.mjs public/buildings/<project>/building.json --units inventory-ids.json
```

The check prints the model's size, its levels with their heights, the units on each floor and the hotspots. It fails when:

- the model is not in metres;
- there are no units, or a unit id appears twice;
- the model has no levels;
- the inventory and the model disagree (`--units` takes a JSON array of unit ids).

`node site/tools/export-tower.mjs <folder>` writes the demo tower as a package. It's a working example of the naming, and the test suite uses it to prove the glTF path end to end.

## What the glTF path does not do yet

- **Furnished interiors** ("La vida dentro") exist only for the demo tower's four procedural plans. With a glTF building, the journey skips from step 02 to step 04.
- **Site context** (city, plaza, mountains) is the shared demo setting, sized for a footprint of about 40 × 31 m. A larger site needs the plaza in `viewer-site.js` extended, or the site modelled into the package.
- **Compressed models** (Draco, meshopt) are not wired in. Keep `building.glb` under about 5 MB.
